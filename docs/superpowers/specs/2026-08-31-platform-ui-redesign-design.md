# 教学实训比赛平台 UI 重设计规范

日期：2026-08-31  
状态：已确认

## 1. 目标

为现有平台建立一套适合长期、高频使用的共享设计系统，并先落地到共享外壳、管理首页和参赛工作台。视觉应专业、克制、清晰，不依赖夸张色彩、装饰性动画或营销页式排版。

本次确认的两个方向：

- 管理端、学习端、运维端采用 **B2 教学仪表台**：冷灰蓝底色、学院蓝主色、默认显示文字且可折叠的侧栏。
- 参赛端采用 **A 赛场控制台**：比赛状态常驻顶部，任务、当前内容和提交检查同时可见。

## 2. 当前事实

- 前端为 Vue 2 + Element UI。
- 管理端、学习端、运维端和参赛端目前都依赖 `PlatformShell` 的基础框架。
- 平台已经支持管理员设置主题色；`platformTheme.js` 会从主题色派生深色和浅色变量。
- 参赛端已经具备服务端倒计时同步、当前赛卷同步、赛前锁定和比赛结束处理逻辑。
- 当前工作区包含大量业务功能改动，本次 UI 重设计不得修改这些业务契约或回退已有功能。

## 3. 范围

### 第一阶段

- 扩展共享颜色、排版、间距、圆角、阴影和状态变量。
- 重构 `PlatformShell` 的桌面折叠行为和视觉样式。
- 新建独立的 `CompetitionShell`，替代参赛端对管理后台外框的直接复用。
- 迁移管理首页，作为共享设计系统的首个代表页面。
- 保持现有路由、权限、接口和业务行为。

### 后续阶段

- 逐步迁移课程、资源、实训、比赛管理和运维页面。
- 每次迁移一个功能域，避免一次性修改全部页面。

### 不在第一阶段

- 暗色模式。
- 菜单信息架构调整。
- 后端接口或数据库改造。
- 大规模页面重写。
- 装饰性 3D、粒子背景、渐变文字或持续运动效果。

## 4. 共享视觉系统

### 4.1 色彩

默认主题：

- 主色：`#386BDC`。
- 页面底色：冷灰蓝，建议 `#F3F6FA`。
- 内容面板：带轻微蓝调的白色，建议 `#FBFCFE`。
- 主文字：深蓝黑，建议 `#162033`。
- 次要文字：冷灰蓝，建议 `#68758A`。
- 边线使用低透明度蓝黑，不使用硬灰色边框。

管理员自定义主题色能力必须保留。主题服务应继续从用户选择的主色派生：

- 强调色。
- 悬停色。
- 柔和选中色。
- 焦点环。
- 主按钮阴影色。

成功、警告、错误和信息色是功能语义，不跟随主题色变化。颜色不能作为唯一状态信号，必须同时提供文字或图标。

### 4.2 排版

- UI 使用系统无衬线字体，中文优先使用系统中文字体。
- 固定字号层级：12 / 14 / 16 / 20 / 24px。
- 页面标题不超过 24px；紧凑面板内标题使用 14 到 18px。
- 字间距保持 0。
- 数字和倒计时使用等宽数字特性，避免数值变化导致布局跳动。

### 4.3 间距与尺寸

- 使用 4px 基础间距：4 / 8 / 12 / 16 / 24 / 32px。
- 卡片圆角统一为 8px。
- 输入框和按钮圆角统一为 6px。
- 表格普通行高约 44px。
- 交互目标最小 44px，图标按钮保持稳定宽高。
- 卡片不嵌套卡片；页面分区优先使用无框布局和浅分隔线。

### 4.4 阴影与层级

- 普通卡片只使用接近不可见的蓝灰阴影或浅边线。
- 大阴影仅用于抽屉、弹窗和悬浮工具。
- 主操作可以使用一次主色阴影，不能让所有按钮和卡片发光。

### 4.5 动效

- 仅保留折叠、切换、加载和操作反馈动效。
- 只动画化 `transform` 和 `opacity`。
- 支持 `prefers-reduced-motion`。
- 禁止无业务意义的弹跳、循环漂浮和滚动展示动画。

## 5. B2 平台外壳

### 5.1 桌面

- 侧栏默认宽 184px，显示图标和文字。
- 用户可主动折叠为 76px；折叠状态显示图标和工具提示。
- 折叠状态保存在当前浏览器，刷新后保持。
- 顶栏高度约 60px，包含页面上下文、搜索、状态区域和账号操作。
- 内容区使用冷灰蓝底色，正文面板使用浅色表面。

### 5.2 平板与手机

- 平板优先使用折叠侧栏。
- 手机使用现有抽屉导航模式，不显示永久侧栏。
- 搜索框在窄屏切换为图标入口，展开后仍可键盘操作。
- 任何页面不得产生整体横向滚动。

### 5.3 页面组件

首批统一以下组件：

- 按钮、图标按钮。
- 输入框、选择器、开关、复选框。
- 标签和状态徽标。
- 表格、分页、筛选工具栏。
- 卡片和统计块。
- 对话框、抽屉、提示消息。
- 加载骨架、空状态、错误状态和成功状态。

## 6. A 赛场控制台

参赛端不继续使用管理后台的侧栏外观。它使用独立 `CompetitionShell`，但复用共享排版、组件、主色和状态规则。

### 6.1 固定顶部状态栏

始终显示：

- 比赛名称。
- 当前赛卷。
- 比赛阶段。
- 服务端同步后的剩余时间。
- 当前账号。
- 网络或计时服务异常状态。

剩余时间使用等宽数字。进入最后时间区间时只改变状态色和提示，不使用闪烁动画。

### 6.2 主导航

使用水平页签：

- 赛规赛程。
- 当前赛卷。
- 实操环境。
- 成果验证。

当前页签清晰突出，导航位置保持不变。赛前不可用页面显示原因，不跳转到空白页面。

### 6.3 三栏比赛工作区

桌面结构：

1. 左侧：比赛模块、题目和完成进度。
2. 中间：当前理论题、实操任务或工具工作区。
3. 右侧：答案保存、实训环境、成果验证、网络和提交状态。

理论题和实操题使用同一个外框：

- 理论题在中间显示题目与答案控件。
- 实操题在中间切换为赛题说明和 VS Code、Jupyter、图像标注等工具。
- 工具切换不离开比赛工作区，不出现另一套独立页面外观。

### 6.4 提交流程

提交按钮前必须显示集中检查结果：

- 未完成题目数量。
- 未保存答案或图片。
- 实训环境状态。
- 成果验证状态。
- 网络与计时服务状态。

提交确认需说明“提交后试卷锁定，只有管理员退回后才能修改”。提交成功后右侧区域切换为只读锁定状态。

### 6.5 比赛状态

界面必须覆盖：

- 尚未开放登录。
- 赛前等待。
- 进行中。
- 暂停。
- 已提交待判分。
- 已退回修改。
- 已完成判分。
- 比赛结束。
- 计时或同步服务异常。

每个状态应给出当前发生了什么、用户还能做什么以及下一步是什么。

### 6.6 响应式处理

- 桌面优先三栏布局。
- 平板将右侧状态区折叠为可展开面板，保留左侧任务导航。
- 手机按“状态栏、当前内容、底部操作”单栏排列；不尝试在手机中完整嵌入桌面代码编辑器。

## 7. 数据与业务边界

- 倒计时继续使用现有服务端时间偏移和定时同步逻辑。
- 当前赛卷继续使用现有 Vuex 同步流程。
- 路由、权限和提交接口保持不变。
- `CompetitionShell` 只负责布局、导航和状态展示，不复制业务请求逻辑。
- 页面业务组件通过现有状态和事件接入新外壳。
- 同步失败时保留最后一次有效状态，并显示可恢复错误提示。

## 8. 可访问性

- 正文文字达到 WCAG AA 对比度。
- 所有交互支持键盘操作并显示焦点状态。
- 图标按钮提供可读名称和工具提示。
- 状态变化使用 `aria-live` 的适当级别，不反复播报每秒倒计时。
- 不能只依靠颜色表达已完成、错误或锁定。

## 9. 验证与验收

### 自动检查

- 主题色派生函数测试。
- `PlatformShell` 展开、折叠和移动抽屉契约测试。
- `CompetitionShell` 状态和导航契约测试。
- 现有路由、权限、倒计时、试卷和提交测试保持通过。
- 前端生产构建通过。

### 视觉检查

- 桌面：1440px 和 1920px。
- 平板：768px 和 1024px。
- 手机：375px 和 414px。
- 检查文字截断、横向滚动、表格密度、倒计时稳定性、弹窗和空状态。

### 第一阶段完成标准

- B2 共享设计变量和组件样式可被所有非比赛端复用。
- `PlatformShell` 支持可持久化折叠且不破坏移动端抽屉。
- 管理首页完成迁移并能验证共享组件效果。
- 参赛端使用 A 赛场控制台外壳，现有比赛功能和接口行为不变。
- 生产构建成功，针对性测试通过，无新增横向滚动或严重可访问性问题。
