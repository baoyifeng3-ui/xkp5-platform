# 简化镜像上传与下发设计

## 目标

将镜像管理改为“上传归档、启用、直接下发”的短链路。文件身份只由镜像仓库名和文件名组成，上传完成后不再依赖 `upload_id`、摘要、审核、导入或发布记录。

## 文件与上传

- 仅接受扩展名为 `.tar` 的文件。
- 保留超级管理员权限、文件名路径安全和最大文件大小限制。
- 不计算、不保存、不校验归档 SHA-256。
- 快检只读取 TAR 头和 `manifest.json`，确认清单可解析且其 `Config`、`Layers` 引用存在；不展开或校验镜像层内容。
- 固定身份为 `imageRepository + originalFilename`。
- 平台将文件写入临时路径，上传完成后以原子移动替换固定归档文件。
- 固定归档已存在时，接口返回“可能覆盖”；用户确认后创建新上传并在完成时替换旧文件。
- `upload_id` 只用于未完成的分片上传。上传完成后，启用和下发只查询固定文件。

## 启用与下发

- 快检通过的归档自动启用，无审核、导入和发布步骤。
- 管理员从启用镜像列表直接选择目标服务器下发。
- 平台根据目标服务器最近上报的镜像清单判断是否存在同名 `repository:tag`；存在时提示覆盖，不存在时直接创建任务。
- 用户确认覆盖后，Agent 下载固定归档并执行 `docker load --input`。
- 平台不在下发前做摘要或镜像层校验。`docker load` 是最终有效性检查。
- `docker load` 失败时任务失败，页面显示 Agent 返回的错误，并提示更换有效的 Docker 镜像归档。

## 服务器资产清单

- Agent 心跳上报 Docker 镜像清单：仓库、标签、镜像 ID、摘要、大小和创建时间。
- Agent 心跳上报全部容器：名称、容器 ID、镜像、状态、运行状态、创建时间和端口。
- 平台保存每台服务器最近一次清单，并提供按服务器查看的镜像和容器两个列表。
- 清单是状态展示和覆盖提示依据，不作为下发权限或归档有效性校验。

## 数据与兼容

- 新流程使用一张当前镜像文件索引表；数据库只保存固定文件身份、路径、大小、启用状态和更新时间。
- 旧镜像审核、导入、发布和推送表暂不删除，旧页面入口停止使用，避免破坏历史数据。
- 服务启动时扫描固定归档目录并修复文件索引，数据库记录不能使不存在的文件变为可下发状态。
- 旧 Agent 不支持完整资产清单，升级 Agent 后启用新页面和同名覆盖提示。

## 验证

- 上传普通文本改名的 `.tar` 时被 TAR 快检拒绝。
- 上传结构正确但层损坏的归档可以启用，下发时由 `docker load` 返回失败原因。
- 同仓库名和文件名二次上传时提示覆盖，确认后固定文件内容被替换。
- 删除数据库中的上传会话后，已完成归档仍可下发。
- 三台 Agent 均能上报镜像和容器清单；同名镜像触发覆盖提示，确认后可继续下发。
