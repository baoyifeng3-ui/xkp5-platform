# XKP5 可追溯版本发布设计

## 目标

先把当前候选平台整理、构建和测试为稳定版本；只有全部验收通过后才正式命名为 `5.0.2`。使 Java、Vue、Agent、数据库迁移、容器模板和安装脚本能够按同一个版本追踪、验证、升级和回滚，解决源码、镜像、Agent 与运行配置混用导致的功能反复失效问题。

## 已确认现状

- 当前可运行 Java 镜像为 `match-v2_java:5.0.1`，摘要为 `sha256:27348ba13349...`。
- 当前可运行 Vue 镜像为 `match-v2_vue:5.0.1`，摘要为 `sha256:3a0f44fa98be...`。
- 最新 Agent 源码提交为 `9567027`，Linux 二进制构建于 2026-09-05 08:15。
- `ui-redesign-live` 保存了最新平台功能，但存在大量未提交修改和构建产物，不能直接作为正式发布基线。
- 当前离线包使用过复用镜像流程，包版本、源码提交与镜像内容不能完全互证。

## 版本模型

正式版本使用 `MAJOR.MINOR.PATCH`。测试阶段只使用不可发布的候选标识，例如 `candidate-<Git短提交>-<构建时间>`。候选栈全部验收通过后才赋予正式版本 `5.0.2`，后续修复依次使用 `5.0.3`、`5.0.4`。失败的候选构建不得占用正式版本号。一个正式版本必须唯一绑定：

- 平台 Git 提交；
- Agent Git 提交；
- Java 镜像摘要；
- Vue 镜像摘要；
- Registry Importer 镜像摘要；
- 数据库最高迁移版本；
- 安装器和离线包 SHA256。

发布清单写入离线包，也安装到目标机。运行中的前后端提供版本信息，便于界面和验证脚本检查实际组件是否匹配。

## 源码基线

以 `ui-redesign-live` 的业务源码为候选基线。提交前排除 JAR、日志、`dist`、临时 Dockerfile、测试镜像归档和本机证书。对剩余修改按以下顺序整理：

1. Java、Vue 和 Agent 业务源码；
2. 数据库迁移；
3. Docker、Compose 和部署脚本；
4. 直接验证这些功能所需的测试；
5. 操作文档。

先建立候选源码快照并运行测试。只有通过编译和关键链路测试的内容才能进入 `release/5.0.2`。无法确认用途的文件保留在原工作树，不进入发布提交，也不删除。

## 构建规则

- Java、Vue 和 Agent 先从候选源码快照重新构建，并使用候选标识。
- 正式 SemVer 发布禁止使用 `--reuse-images`。
- 验收通过后，将候选镜像的同一摘要标记为不可变版本 `5.0.2`；`latest` 只能在此后指向相同摘要。
- Docker 镜像写入版本、Git 提交和构建时间标签。
- 离线包生成器检查 Java、Vue、Agent 和发布清单版本一致；不一致时终止打包。
- 同一版本号已存在时拒绝覆盖，修复后必须递增 PATCH。

## 本机升级

升级前备份当前数据库并记录现有容器、镜像摘要和网络。新版本使用独立项目名和网络启动，避免与 `competition-*`、`xkp5test-*` 或历史容器共享 `java` 等 DNS 别名。

候选栈连接现有数据副本完成迁移和验证。验证通过后才标记为 `5.0.2`，并将 `19140`、`19141` 和 `19443` 切换到正式栈。旧 `5.0.1` 镜像和升级前数据库备份至少保留到 `5.0.2` 完成端到端验收。

## Agent 与容器模板兼容

管理平台在下发环境命令前检查 Agent 协议版本和模板要求。Agent 版本不满足时拒绝创建环境，并返回明确的升级提示。

Agent 安装和升级验证以下主机条件：

- Docker 与所需 runtime 可用；
- code-server TLS 路径存在且文件类型正确；
- 镜像已缓存且摘要匹配；
- 端口池没有冲突；
- 管理端 TLS 与 Agent 身份有效。

模板记录所需 Agent 协议版本。证书文件、目录或镜像不匹配时，环境进入明确的 `DEGRADED` 状态，不无限停留在 `STARTING`。

## 恢复机制

自动恢复只处理安全且幂等的状态：

- 过期租约重新入队；
- Agent 恢复在线后重试尚未执行的命令；
- 超时的 `STARTING`、`STOPPING` 和 `RESTORING` 操作转为 `DEGRADED`；
- 平台启动时核对数据库状态与 Agent 报告的实际容器状态。

管理员页面提供“重新检测”和“恢复环境”操作。“重新检测”只同步状态；“恢复环境”先停止并清理该环境的残留容器，再用同一模板和端口重新创建。任何会覆盖用户数据的恢复必须单独提示并保留快照。

## 验收门槛

候选版本必须自动完成：

1. Java 编译和相关测试；
2. Vue 生产构建和契约测试；
3. Agent 测试和 Linux 二进制构建；
4. 新数据库安装与现有数据库升级；
5. 登录、角色导航、授权导出和授权导入接口；
6. Agent 注册、心跳、命令轮询和回执；
7. 创建、启动、访问、停止、恢复和删除临时比赛环境；
8. 离线包内部校验和外层 SHA256；
9. 从 `5.0.1` 回滚并恢复服务。

任何一项失败都不得分配正式版本号、更新 `latest` 标签或替换现有运行栈。

## 交付结果

- `release/5.0.2` 可追溯源码提交；
- `match-v2_java:5.0.2`、`match-v2_vue:5.0.2` 和版本化 Agent；
- 含完整发布清单的 `xkp5-offline-5.0.2.tar.gz`；
- 与离线包匹配的 `install-xkp5-offline.sh`；
- 本机唯一运行栈和升级前数据库备份；
- 一条可重复执行的版本验收命令。
