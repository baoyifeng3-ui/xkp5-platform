# 容器模板选择已发布镜像版本设计

## 目标

发布容器模板时不再手工填写 Docker 镜像引用。管理员只能从镜像仓库中选择已经导入完成并发布的不可变镜像版本，模板保存该版本的 Registry 摘要。

## 模板发布流程

1. 页面加载镜像仓库的已发布版本列表。
2. 图像标注组件只显示 `ANNOTATION` 发布版本；代码编辑组件只显示 `EDITOR` 发布版本。
3. 选项显示镜像组、版本、仓库标签和 `sha256:` 摘要。
4. 选择后自动填充镜像引用和摘要，不允许手工修改。
5. 发布模板时后端验证发布版本存在、组件类型匹配、状态为可用，并将摘要写入模板配置指纹。

## 容器创建规则

- 比赛容器和实训容器创建时选择模板的固定版本。
- 模板保存后，后续镜像仓库发布新版本不会自动改变已有模板或运行容器。
- 使用新镜像必须发布新模板版本，或在明确的恢复/升级流程中选择新模板。
- 已停用的镜像发布版本和模板版本不能用于新建容器；已有容器继续使用原固定摘要。
- Agent 创建容器时使用摘要对应的镜像，不使用可变的 `latest` 标签作为唯一依据。

## 错误处理

- 没有可用发布版本时，组件选择器显示空状态并禁止发布模板。
- 镜像版本被撤销、摘要不存在或组件不匹配时，后端拒绝发布并返回明确错误。
- Registry 暂时不可用时，不影响已有模板和容器，只阻止创建新的模板版本。

## 验证

- 前端测试覆盖组件筛选、摘要显示和无可用版本禁用发布。
- 后端测试覆盖发布版本不存在、组件类型不匹配、停用版本和摘要固定。
- 本地冒烟流程验证“镜像上传 → 审批 → 导入 → 发布 → 选择模板 → 创建容器”。
