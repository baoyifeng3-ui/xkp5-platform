# XKP5.0 处理服务器管理员手册

普通管理员在一级“设备管理”中查看处理服务器状态，不能添加、修改、禁用、移除处理
服务器，也不能生成注册码。服务器身份、端口和容器资源限制统一由超级管理员维护。

## 状态与指标

列表显示设备名称、固定 IP、Agent 版本、在线状态和最新资源占用。服务器在最后一次被
管理端接受的心跳后 15 秒内为在线；超过 15 秒显示离线。短暂网络中断恢复后会自动
重连，不需要管理员修改设备。

| 指标 | 含义 |
| --- | --- |
| CPU / 内存 | 宿主机实时使用率；内存详情包含总量与已用量。 |
| GPU / 显存 / 温度 | NVIDIA 驱动通过 NVML 返回的数据；缺失时显示 `--`。 |
| 系统盘 | Ubuntu 根文件系统使用率。 |
| 工作目录盘 | 实训和比赛共享目录所在挂载点的使用率。 |
| Docker | Docker Engine 可用状态、版本、运行容器和环境数量。 |

历史图按分钟聚合并保留 30 天。某一采集项失败不会让整台服务器离线：页面会显示稳定
错误码，其他成功指标继续更新。例如工作目录未挂载时 CPU、内存和系统盘仍可查看。

## 处理告警

1. 先记录设备名称、发生时间、在线状态和错误码。
2. 在线但单项指标缺失时，把错误码交给超级管理员或现场运维，不要反复刷新或修改设备。
3. 设备离线超过 15 秒时，确认同一局域网是否可达，再通知运维检查 Agent systemd 服务。
4. 不要要求运维开放 Docker TCP、关闭 TLS 校验或发送 Agent 身份配置。

普通管理员可以在设备详情中发送 Wake-on-LAN 开机包，或向在线 Agent 提交安全关机
命令。开机提示只表示数据包已发送，不代表服务器已经上线；请等待列表状态变化。关机
操作需要二次确认，页面会依次显示等待接收、已送达、等待离线确认、已完成或失败原因。

普通管理员不能注册、启用、停用或移除处理服务器，也不能打开 root 终端。普通管理员
可以在授权有效时启动、停止和还原已分配的训练环境；还原会重建容器但保留共享工作区，
必须确认当前环境没有仍需保留的容器内临时状态。页面在 Agent 确认前显示等待处理或
执行中，不会把已提交命令直接显示为成功。

## 比赛模式与槽位绑定

“竞赛管理 → 模式与环境”固定显示每台可见处理服务器的 1 至 4 号槽位。槽位必须已经由
超级管理员创建双容器并显示 `READY`，才能绑定普通用户。没有容器信息的槽位不能绑定；
同一 Agent 的四个槽位可以分别绑定不同用户。解绑前容器必须处于可安全变更的停止状态。

进入比赛模式前：

1. 确认只绑定实际需要实操环境的用户；未绑定槽位不会启动容器。
2. 确认模式迁移列表没有仍在执行或失败的旧迁移。
3. 点击进入比赛模式，并精确输入 `ENTER COMPETITION`。
4. 等待所有 Agent 迁移完成；失败时记录迁移编号和失败码，交由超级管理员修复并重试。

模式变更会递增 `modeGeneration`。所有普通用户的旧登录在下一次请求时收到
`PLATFORM_MODE_CHANGED` 并退出，重新登录后才能进入新的界面。比赛模式下，未绑定槽位的
用户仍可查看试卷并答题，但“比赛实操”显示未分配环境，不提供图像标注或代码编辑链接。
已绑定用户也只有在双容器状态为 `RUNNING` 且服务器完成校验后才看到后端返回的链接。

退出比赛模式时精确输入 `EXIT COMPETITION`。普通用户需再次登录进入实训界面；平台只
恢复进入比赛前快照中实际运行的实训环境，不会启动原本停止的环境。
