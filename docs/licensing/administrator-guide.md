# XKP5.0 平台授权管理员手册

普通管理员负责平台激活和续期。超级管理员只能查看授权诊断、审计记录并触发重新
校验，不能在平台内生成许可证。

## 首次激活

1. 登录普通管理员界面，从主页授权状态进入“平台授权”。
2. 点击“生成平台信息”，随后下载 `.xkpreq` 文件。
3. 将该文件交给授权运营方，不要修改文件内容。
4. 收到 `.xkplic` 后回到同一页面导入。
5. 确认状态为“已激活”，并核对单位、到期时间和处理服务器上限。

平台信息请求只能下载一次。文件丢失时重新生成，不要使用旧请求。续期流程与首次
激活相同，应在“即将到期”阶段完成。

## 状态说明

| 状态 | 含义与处理 |
| --- | --- |
| 未激活 | 尚未导入有效许可证，导出平台信息并申请授权。 |
| 已激活 | 授权正常，可使用实训和比赛容器。 |
| 即将到期 | 距到期不足 30 天，立即申请续期。 |
| 已过期 | 容器全部关闭且不能启动，导入新的有效许可证。 |
| 授权无效 | 文件、签名或平台绑定校验失败，联系运营方排查。 |
| 系统时间异常 | 系统时间发生回退，先修正 Ubuntu/NTP 时间，再由超级管理员重新校验。 |

授权失效、过期或检测到时间回退时，平台采取关闭保护：实训和比赛容器均不能启动。

## 常见导入错误

- `FINGERPRINT_MISMATCH`：许可证属于另一台管理服务器。用当前平台重新导出信息。
- `ENVIRONMENT_MISMATCH`：开发许可证和 Ubuntu 正式许可证混用。申请正确环境的文件。
- `INVALID_SIGNATURE` 或 `UNKNOWN_KEY`：文件被改动，或服务器未部署对应公钥。不要反复
  导入，保留原文件并联系授权运营方或超级管理员。
- `REQUEST_NOT_FOUND` / `REQUEST_ALREADY_USED`：请求不存在或已使用。重新生成平台信息。
- `NOT_YET_VALID` / `EXPIRED`：授权时间范围不适用。核对服务器时间和签发日期。
- `CLOCK_ROLLBACK`：禁止通过回拨时间延长许可证。恢复可靠 NTP 时间后重新校验。

导入失败不会停用当前有效许可证。不要编辑 `.xkpreq`、`.xkplic` 或数据库授权记录。
超级管理员可在“授权诊断”查看密钥标识、环境、主机指纹摘要和审计原因码；页面不会
显示签名、挑战值、原始主机标识或完整许可证内容。
