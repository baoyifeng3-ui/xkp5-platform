## 1. 平台概览

平台分为三类工作区：

- **学习工作台**：普通用户学习课程、使用实训环境、管理资源和进行模型验证。
- **管理工作台**：管理员管理课程、资源、用户、实训环境和比赛业务。
- **平台运维**：超级管理员管理处理服务器、容器模板、镜像仓库、账号和授权。

平台的实训环境由图像标注、代码编辑器、Jupyter 和模型服务组成。代码编辑器与图像标注使用同一个宿主机工作目录，但容器内路径不同：代码编辑器为 `/home/student/data`，图像标注为 `/root/data`。

## 2. 登录与角色

打开平台地址后输入账号和密码登录。登录成功后，平台根据账号角色显示对应工作区；普通用户不能访问管理员和运维页面。

如果平台刚切换了实训模式或比赛模式，需要重新登录。登录页提示“登录已失效”时，先退出旧页面，再重新打开平台地址。

### 2.1 登录步骤

1. 使用 Chrome 或 Edge 打开平台地址。
2. 输入管理员分配的账号和密码。
3. 点击“登录”。
4. 首次登录若要求修改密码，按页面要求完成后重新登录。
5. 检查左侧菜单和页面标题，确认当前工作区正确。

### 2.2 角色与菜单

| 角色 | 登录后的工作区 | 主要权限 |
| --- | --- | --- |
| 普通用户 | 学习工作台 | 课程学习、资源使用、个人实训环境、模型验证 |
| 管理员/教师 | 管理工作台 | 用户、课程、资源、实训、比赛、学情管理 |
| 超级管理员 | 平台运维 | 处理服务器、镜像、模板、管理员、授权和系统维护 |

### 2.3 登录异常

- 显示“当前平台模式不允许访问此功能”：管理员已经切换工作模式，退出后重新登录。
- 显示“仅普通管理员可以执行此操作”：当前账号角色不符合该操作要求。
- 登录成功但页面空白：先强制刷新；仍异常时记录当前 URL、账号角色和时间交给管理员。
- 不要通过修改浏览器地址绕过权限。后端仍会执行角色和模式校验。

## 3. 学习工作台

### 3.1 课程平台

进入“课程平台”后选择课程，可以查看课程简介、课程大纲、课程目录、PPT、视频和数据资源。

课程目录中的资源支持在线阅读。需要使用实训环境时，点击题目或课程区域中的实训入口。环境未启动时页面显示“实训环境正在启动”，容器就绪后自动显示对应工具。

课程学习页面支持课程内容与实训环境分屏。拖动中间分隔条可以调整两侧宽度；按住分隔条后，即使鼠标移入右侧容器页面，也可以继续拖动。

![课程学习与实训环境](../../screenshots/screenshot-20260825-005438.png)

> 截图说明：左侧为课程材料，右侧为嵌入式实训工具；中间分隔条可以拖动。

#### 进入课程

1. 点击左侧“课程平台”。
2. 在课程列表中选择需要学习的课程。
3. 使用“课程简介”“课程大纲”“课程目录”“PPT”“视频”“数据资源”标签切换内容。
4. 点击资源名称打开课程内容。
5. 学习完成后点击“完成本资源学习”，平台记录学习进度。

#### 使用课程分屏

1. 在课程目录中点击“进入实训”或对应工具入口。
2. 若环境未运行，等待页面显示“实训环境正在启动”。
3. 环境启动完成后，实训工具显示在右侧。
4. 按住中间分隔条左右拖动，调整课程材料和实训区域宽度。
5. 点击“全屏”可放大工作区域；退出全屏后恢复分屏布局。

成功判断：环境状态显示“运行中”，右侧工具能够加载，拖动分隔条时不会与鼠标脱离。

### 3.2 实训环境

进入“实训环境”可以查看当前用户可用环境及运行状态：

- **启动中**：正在创建或启动容器。
- **运行中**：图像标注、VS Code、Jupyter 等入口可用。
- **已停止**：点击启动后重新创建或启动容器。
- **异常**：检查处理服务器、镜像和 Agent 状态。

普通用户只能使用分配给自己的环境。环境被删除后，关联容器也应由 Agent 清理。

#### 启动环境

1. 点击左侧“实训环境”。
2. 在顶部下拉框选择当前环境。
3. 点击需要使用的工具，例如“图像标注”或“VS Code”。
4. 环境停止时，平台自动提交启动任务。
5. 启动期间不要重复点击。等待进度提示结束。
6. 页面显示“运行中”后，工具自动嵌入页面。

#### 工具说明

| 工具 | 用途 | 容器内主要目录 |
| --- | --- | --- |
| 图像标注 | 创建项目、上传或连接数据、标注图片 | `/root/data` |
| VS Code | 编写代码、使用终端、训练和导出模型 | `/home/student/data` |
| Jupyter | Notebook 实验和数据分析 | `/home/student/data` |
| T100 | 模型推理和验证服务 | 由平台端口映射提供 |

#### 停止与恢复

- 停止环境只停止容器，不删除共享目录。
- 恢复环境会删除并重新创建容器，但保留共享目录。
- 修改镜像、启动命令或资源限制后，必须恢复环境，旧容器才会应用新配置。
- 容器内未放在共享目录中的临时文件可能在恢复时丢失。

### 3.3 共享目录

两个工具使用同一个宿主机目录：

```text
宿主机:     /srv/xkp/environments/<环境相对路径>/
代码编辑器: /home/student/data/
图像标注:   /root/data/
```

在代码编辑器中创建的文件，应能在图像标注中通过 `/root/data` 看到。比赛或课程提供的固定数据集地址属于管理服务器的数据集目录，不等于上述共享工作目录。

#### 验证共享目录

在 VS Code 终端执行：

```bash
mkdir -p /home/student/data/share-test
date > /home/student/data/share-test/check.txt
```

然后在图像标注容器对应的共享目录中检查：

```text
/root/data/share-test/check.txt
```

若图像标注的“连接共享文件”提示无数据，管理员应检查 CVAT 子容器的 `/home/django/share` 是否映射到外层 `/root/data`，以及宿主机目录权限是否至少允许服务用户读取。

### 3.4 资源中心

资源中心包含公共资源库、交换空间和作业空间。

- 点击文件名：打开浏览器支持的预览类型。
- 点击“下载”：下载到当前电脑。
- 点击“发送到容器”：将文件下发到当前实训环境。

下发文件保存到：

```text
<共享目录>/resource-downloads/
```

因此代码编辑器和图像标注都能访问同一份文件。图片、PDF、TXT、CSV、LOG、MD、JSON、HTML 等类型通常支持浏览器预览；DOC/DOCX、XLS/XLSX、PPT/PPTX、ZIP 等类型通常直接下载。

#### 上传资源

1. 进入“交换空间”或“作业空间”。
2. 如需分类，先点击“新建目录”。
3. 点击“上传文件”，选择本机文件。
4. 等待上传完成，再点击“刷新”。
5. 检查文件名称、大小、上传人和时间。

公共资源库普通用户只读，由管理员维护。

#### 下载到电脑

1. 点击文件所在行的“下载”。
2. 浏览器直接保存文件，不应只打开图片预览。
3. 在浏览器下载列表中确认文件名和大小。

#### 发送到实训环境

1. 确认当前账号已经绑定实训环境。
2. 确认处理服务器在线、环境可以正常启动。
3. 点击文件所在行的“发送到容器”。
4. 等待“文件已下载到实训环境”的提示。
5. 在 VS Code 中打开：

```text
/home/student/data/resource-downloads/
```

6. 图像标注侧对应目录为：

```text
/root/data/resource-downloads/
```

提示“资源下发失败”时，管理员应检查最新 `TRANSFER_FILE` 命令，而不是只检查浏览器下载。

### 3.5 模型验证

进入“模型验证”后上传图片或输入图片 URL，再点击“开始验证”。平台会使用当前实训环境的 T100 服务进行推理。

模型验证使用当前赛卷类型；如果没有有效赛卷，默认使用 A 卷。验证失败时先确认环境处于“运行中”，再检查模型服务和图片内容。

#### 上传图片验证

1. 点击“模型验证”。
2. 选择“上传图片”。
3. 点击“选择图片”，选择 JPG 或 PNG 文件。
4. 文件名显示后点击“开始验证”。
5. 等待结果图片和推理信息显示。

#### 图片 URL 验证

1. 切换到“图片 URL”。
2. 输入处理服务器和管理服务器都可访问的 HTTP/HTTPS 图片地址。
3. 点击“开始验证”。

成功判断：页面显示“模型验证完成”，并呈现服务返回的结果。若提示 `paperType` 无效，确认当前赛卷为单个英文字母，例如 `A` 或 `B`。

## 4. 比赛模式

### 4.1 答题界面

比赛模式下进入“当前赛卷”查看题目。实操题会显示题目要求、截图要求和“进入代码环境”或“进入标注环境”入口。

#### 答题步骤

1. 登录比赛账号。
2. 点击“当前赛卷”。
3. 检查顶部赛卷名称和剩余时间。
4. 按模块顺序完成题目。
5. 客观题或文字题修改后及时点击“保存答案”。
6. 实操题按截图要求上传结果图片，再点击“保存图片”。
7. 提交前检查右侧“当前完成度”“答案保存”“成果验证”和“试卷状态”。
8. 确认无误后提交试卷。

提交后试卷会锁定。只有管理员退回后才能继续修改。

### 4.2 比赛实操

实训入口会打开比赛实操页，并根据当前赛题自动选择图像标注或代码编辑环境。环境启动期间显示启动状态，运行后直接嵌入当前页面。

页面控制项：

- **全屏**：让实训界面占满屏幕，同时保留顶部操作按钮。
- **比赛帮助**：显示当前赛卷的环境依赖和数据资源地址。
- **查看赛题**：查看当前实操题名称、答题要求和截图要求。
- **返回答题界面**：回到当前赛卷答题页。

#### 进入实操环境

1. 在实操题中点击“进入代码环境”或“进入标注环境”。
2. 平台打开比赛实操页，不会停留在 `about:blank`。
3. 环境为停止状态时，平台自动启动并轮询状态。
4. 环境运行后，根据当前赛题嵌入唯一对应工具，不提供工具切换。
5. 点击“查看赛题”可临时查看当前题目名称、操作要求和截图要求。
6. 点击“比赛帮助”查看当前赛卷的数据资源地址。
7. 点击“返回答题界面”回到 `/Question`。

#### 全屏操作

1. 点击“全屏”。
2. 全屏后仅保留控制栏和实训工具。
3. 控制栏保留“返回答题界面”“取消全屏”“比赛帮助”“查看赛题”。
4. 点击“取消全屏”或按 `Esc` 退出。

### 4.3 比赛帮助资源

帮助中的数据集统一从管理服务器下载，例如：

```bash
wget http://10.247.115.41:19140/dataset/A/requirements.txt
```

请根据帮助清单中的实际文件名下载。下载到容器后，建议保存到容器自己的 `dataset` 目录；该目录与平台共享工作目录用途不同。

常用下载方式：

```bash
mkdir -p /home/student/contest/dataset
cd /home/student/contest/dataset
wget http://10.247.115.41:19140/dataset/A/requirements.txt
wget http://10.247.115.41:19140/dataset/A/u1.tar.gz
```

资源统一由管理服务器提供。帮助清单会根据当前赛卷自动使用 `/dataset/A/`、`/dataset/B/` 等目录。

## 5. 管理工作台

管理员可以使用以下模块：

- **用户管理**：创建、导入、启用、禁用和删除用户，分配服务器槽位。
- **课程管理**：创建课程、章节和课程资源，配置课程实训入口。
- **资源管理**：管理公共资源、课程资源和作业资源。
- **实训环境**：创建、启动、停止、恢复和强制删除环境。
- **比赛管理**：配置赛卷、题目、比赛时间、比赛账号和比赛环境。
- **学情分析**：查看用户学习进度、资源完成情况和教师评价。

删除实训环境时，平台会向对应 Agent 下发删除命令。若服务器离线，数据库状态可能暂时停留在删除中；服务器恢复后应重新执行恢复或删除操作。

### 5.1 用户管理

#### 创建单个账号

1. 进入“平台管理 → 用户管理”。
2. 点击“创建账号”。
3. 填写账号、初始密码、备注和必要的自定义字段。
4. 根据需要选择处理服务器槽位。
5. 点击“保存”。

#### 批量创建账号

1. 点击“批量创建账号”。
2. 设置创建数量。
3. 选择有足够空闲槽位的处理服务器。
4. 点击“创建”。
5. 若提示“所选服务器空闲槽位不足”，减少数量或增加服务器。

#### 槽位规则

- 同一槽位只能绑定一个账号。
- 管理员账号的教学槽位功能已记录为后续版本，当前版本暂不开放管理服务器固定教学槽位。
- 已有环境的账号需要通过迁移或先删除环境，再更换槽位。

### 5.2 课程管理

1. 点击“课程与资源 → 课程管理”。
2. 点击“新建课程”，填写课程名称、分类、简介和封面。
3. 保存课程后点击“编辑课程内容”。
4. 创建章节并设置顺序。
5. 上传 PDF、PPT、视频或数据文件。
6. 将资源绑定到章节，设置资源类型和是否启用。
7. 需要实训时绑定对应的容器模板。
8. 使用管理员预览确认普通用户看到的页面。

### 5.3 容器模板

创建模板前，镜像必须已经发布且推送到目标处理服务器。

1. 进入“容器模板”。
2. 点击“发布模板”。
3. 输入模板名称。
4. 选择组件类型：图像标注或代码编辑。
5. 选择与组件类型匹配的已发布镜像。
6. 配置 CPU、内存和 GPU 参数。
7. 点击“发布”。

资源参数规则：

- CPU、内存设置为 0 表示不限制。
- 仅开启 GPU且未启用 MPS/计算比例/显存限制时，Agent 只使用 `runtime=nvidia`。
- 启用 MPS 后，才注入 MPS 计算比例和相关目录。
- 修改模板不会自动修改已存在容器，必须恢复环境。

### 5.4 创建实训环境

1. 确认用户已绑定处理服务器槽位。
2. 确认处理服务器在线且镜像已存在。
3. 进入“实训管理 → 实训环境”。
4. 点击“创建实训环境”。
5. 选择用户、环境类型和模板。
6. 检查自动分配的服务器、槽位和端口。
7. 提交创建并等待状态更新。

成功判断：双容器创建完成，环境状态为“已停止”或“运行中”，组件和端口信息完整。

### 5.5 删除实训环境

1. 确认用户已保存共享目录外的重要文件。
2. 在环境行点击“全部强制移除”或删除操作。
3. 确认删除环境及服务器容器。
4. 等待 Agent 返回 `ENVIRONMENT_DELETED`。
5. 在处理服务器使用 `docker ps -a` 确认两个组件容器均已删除。

删除操作按平台所有权标签和环境 ID 清理，不应依赖旧配置指纹。服务器离线时无法立即删除物理容器。

## 6. 平台运维

超级管理员可以使用：

- **处理服务器**：添加 Agent、检查在线状态、查看资源指标和部署 Agent。
- **容器模板**：配置图像标注、代码编辑、Jupyter、T100 镜像及资源限制。
- **镜像仓库**：上传、发布和推送镜像到处理服务器。
- **管理员账号**：维护管理员和超级管理员。
- **授权诊断**：查看安装实例、授权编号、可信时间、主机指纹和授权审计。

处理服务器 Agent 需要在线并能访问管理服务器。新建或恢复环境时，Agent 才会按最新模板重新创建容器；已经运行的旧容器不会因为模板修改自动重建。

### 6.1 添加处理服务器

1. 进入“平台运维 → 处理服务器”。
2. 点击“添加服务器”。
3. 填写固定 IP、备注名称、SSH 用户、密码、端口和工作目录。
4. 使用连通性检查确认 SSH 可达。
5. 选择远程部署 Agent，或下载部署包后离线安装。
6. 等待 Agent 首次上报。

成功判断：服务器显示“在线”，能看到 CPU、内存、GPU、磁盘和容器指标。

处理服务器生产要求：Ubuntu、Docker、`sysbox-runc`、`nvidia` runtime、NVIDIA 驱动和足够的工作盘空间。

### 6.2 推送镜像

1. 进入“镜像仓库”。
2. 上传 Docker save 格式镜像归档。
3. 等待上传、归档校验和摘要计算完成。
4. 审核并发布镜像版本。
5. 打开“推送进度”，选择目标处理服务器和策略。
6. 提交推送。

推送状态：等待 Agent、下载归档、导入镜像、健康检查、完成或失败。若一直等待 Agent，检查服务器心跳；若 `status 400`，检查归档下载接口和镜像文件。

### 6.3 授权诊断

1. 进入“授权诊断”。
2. 查看授权状态、安装实例、授权编号、可信时间、主机指纹和公钥标识。
3. 点击“导出平台信息”生成授权申请信息。
4. 选择授权文件后点击“导入授权”。
5. 点击“重新校验”。

“可信时间”是平台防止系统时间回拨所维护的时间，不代表授权到期时间。永久授权是否有效应以授权内容和校验结果为准。

### 6.4 Agent 更新

Agent 更新后：

1. 确认 `systemctl is-active xkp-agent` 返回 `active`。
2. 确认三台处理服务器二进制摘要一致。
3. 新规则只对新建或恢复容器生效。
4. 不要在教学或比赛进行中批量恢复环境。

## 7. 常见问题

### 实训环境一直显示启动中

检查处理服务器 Agent 是否在线、镜像是否存在、端口是否被占用。查看“实训环境”页面刷新状态，必要时由管理员恢复环境。

### 图像标注登录后提示共享数据加载失败

优先检查共享目录权限。CVAT 子容器需要读取外层图像标注容器的 `/root/data`；目录不能是仅 root 可读的 `0700`。

### VS Code 或图片无法加载

确认 code-server 已启动并使用 HTTPS 证书。旧容器可能仍使用旧启动命令，需要恢复或重建容器。

### 训练出现“段错误”

先确认是否在课程容器中运行；同镜像不代表运行参数相同。对比容器的 GPU runtime、DeviceRequests、环境变量、共享内存、内存限制、启动命令和挂载目录。TensorFlow 的弃用警告通常不是致命原因。

### 模型验证提示 paperType 无效

确认当前比赛或课程已选择有效赛卷。平台要求 `paperType` 为单个英文字母，例如 `A` 或 `B`。

### 资源下发失败

确认当前环境属于当前用户、Agent 在线且容器已运行。资源下发通过管理服务器文件代理获取文件，再写入环境的 `resource-downloads` 目录。

### 比赛环境显示 about:blank

旧页面可能先创建空窗口再等待环境。更新前端后应先进入比赛实操状态页，再启动并嵌入环境。确认浏览器加载的是最新前端资源。

### 比赛环境实际运行但页面显示不可用

管理员检查 `training_environment` 中该用户的 `COMPETITION` 环境状态，并检查用户是否绑定正确槽位。页面启动请求失败后应再次查询真实状态。

### code-server 提示 insecure context

code-server 虽然可以显示，但剪贴板和 WebView 可能受限。检查证书文件和 HTTPS 启动参数；旧容器需要恢复后才会加载新启动命令。

### TensorFlow 在 tf.Session() 段错误

如果同服务器、同镜像、同代码的手动容器可以训练，应对比 Docker 运行参数。当前平台的纯 GPU 模式应只使用 `runtime=nvidia`，不额外注入 MPS 和 GPU DeviceRequests；MPS 或 GPU 限制只有明确启用时才生效。

## 8. 标准业务流程

### 8.1 新建课程实训的推荐顺序

1. 超级管理员接入处理服务器。
2. 超级管理员上传并推送镜像。
3. 超级管理员发布图像标注和代码编辑模板。
4. 管理员创建用户并分配槽位。
5. 管理员创建课程和课程资源。
6. 管理员创建实训环境并绑定课程。
7. 管理员预览课程和实训入口。
8. 普通用户登录、启动环境并验证共享目录。

### 8.2 新建比赛的推荐顺序

1. 配置赛卷和题目。
2. 创建比赛账号。
3. 创建比赛双容器环境。
4. 将账号绑定到 `READY` 比赛槽位。
5. 检查比赛帮助中的数据资源地址。
6. 设置比赛时间和当前赛卷。
7. 进入比赛模式。
8. 让比赛用户重新登录。
9. 使用至少两个账号验证环境可以分别启动。
10. 验证答题保存、截图上传、实操嵌入、模型验证和试卷提交。

## 9. 上线验收清单

### 普通用户验收

- 能登录并看到学习工作台。
- 能打开课程材料并拖动分屏条。
- 能启动图像标注和 VS Code。
- 两个容器能看到同一共享文件。
- 资源能下载到电脑和实训环境。
- 模型验证能返回结果。

### 管理员验收

- 能创建用户、课程和实训环境。
- 能启动、停止、恢复和删除环境。
- 删除环境后处理服务器不残留对应容器。
- 能配置比赛账号、赛卷和比赛槽位。

### 比赛验收

- 至少两个不同比赛用户可以进入各自环境。
- 实操页不会出现 `about:blank`。
- 全屏时保留必要控制按钮。
- 比赛帮助显示当前卷的数据资源。
- 查看赛题显示当前实操题内容。
- 返回答题页后答案仍保留。

### 运维验收

- 所有 Agent 在线且版本一致。
- 镜像摘要在目标服务器一致。
- 管理后端健康检查正常。
- 授权状态有效，可信时间正常推进。
- 管理端、Agent 和容器日志没有持续错误。
